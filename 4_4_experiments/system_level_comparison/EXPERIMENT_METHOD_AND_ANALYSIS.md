# RFLP Multi-Agent versus Single-Agent Comparison

## 1. Objective

This experiment evaluates the multi-agent RFLP/XLanguage model-generation workflow against a sequential single-agent baseline. The evaluation focuses on final requirement, use-case, logical, and physical model artifacts rather than general natural-language response quality.

The central question is whether the multi-agent workflow produces more complete, compilable, structurally coherent, and logically consistent RFLP/XLanguage models under a shared task set and evaluation protocol. Existing large language model APIs generate the model text, while local syntax validation, XCom compilation, and an independent LLM judge provide the evaluation evidence.

## 3. Experimental Groups

### 3.1 Multi-Agent Workflow

The multi_agent_current condition represents the Step1-Step13 RFLP/XLanguage workflow reported in the manuscript. It is the treatment group and uses stage-specific generation, structural checks, semantic checks, tool calls, and bounded repair.

### 3.2 Sequential Single-Agent Baseline

The single_agent_sequential_oneshot condition uses one agent role across four sequential calls:

1. Requirement model generation.
2. Use-case model generation.
3. Logical XLanguage model generation.
4. Physical XLanguage model generation.

Each call receives the models generated by preceding calls. The prompt also provides syntax guidance, a one-shot example, and the original task requirement. Syntax validation and XCom evaluation are applied after all four model texts have been generated.

## 4. Fairness Controls

Both groups use the same 24 tasks, final evaluation criteria, model family, temperature, user task text, repair budget, XCom timeout, and memory policy. The single-agent baseline receives sequential context and syntax examples so that it generates the same four final model categories evaluated for the multi-agent workflow.

The blinded LLM judge receives the original requirement plus the final logical and physical model texts. Group names, file paths, intermediate artifacts, syntax results, and XCom results are separated from the judge input. This separation allows semantic quality and toolchain executability to be assessed independently.

## 7. Evaluation Metrics

### 7.1 Hard Metrics

| Metric | Definition |
| --- | --- |
| req_usecase_syntax_pass | Requirement and use-case models pass their syntax validators |
| logical_xcom_compile_pass | Final logical model passes XCom compilation |
| physical_xcom_compile_pass | Final physical model passes XCom compilation |
| all_hard_pass | All three hard checks pass |

These binary metrics measure compatibility with the local modeling toolchain. XCom compilation provides direct evidence that a model can enter the compilation and simulation workflow.

### 7.2 Blinded LLM-Judge Metrics

An independent LLM judge assigns scores from 1 to 5 for logical-architecture reasonableness, physical-architecture reasonableness, logical-simulation meaningfulness, physical-simulation meaningfulness, and logical-physical consistency. The final metric examines subsystem-component mappings, interfaces, events, objectives, observables, and simulation variables.

Tasks lacking either final logical or final physical output receive a score of 1 for all five LLM-judge metrics. Results are reported as both paired valid-output means and all-task means.

## 9. Interpretation

The hard metrics show that the multi-agent workflow provides substantially stronger XCom executability. The paired valid-output analysis gives a more specific view of semantic quality: the single-agent baseline performed better on logical presentation, whereas the multi-agent workflow performed better on physical modeling and cross-level consistency.

For paired valid outputs, the multi-agent logical-physical consistency mean was 3.23 compared with 2.85 for the single-agent baseline. This result is consistent with the use of intermediate contracts, logic-to-physics mappings, and context constraints during physical-model generation.

The comparison also reveals a trade-off between long-workflow completion and model executability. The multi-agent condition had more stage and timeout failure points, but its completed artifacts were much more likely to enter the XCom toolchain.

## 10. Conclusions

1. The multi-agent workflow outperformed the sequential single-agent baseline in compilable RFLP/XLanguage model generation, with all-hard-check pass counts of 13/24 and 0/24, respectively.
2. The single-agent baseline produced coherent final texts and higher all-task semantic scores, but these texts did not pass logical or physical XCom compilation.
3. Among paired valid outputs, the multi-agent workflow achieved stronger physical-model quality and logical-physical consistency.
4. Completion rate and runtime stability remain the principal improvement targets for the multi-agent workflow.
5. Hard metrics and blinded LLM scores provide complementary evidence: the former measure executability, whereas the latter measure visible structural and simulation quality.

## 11. Further Evaluation Directions

Future evaluations can add paired significance tests for hard metrics, nonparametric tests for ordinal LLM scores, repeated scoring with multiple judges, finer failure categorization, and a single-agent condition with validation-guided repair.
